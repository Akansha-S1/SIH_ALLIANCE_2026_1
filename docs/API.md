# API Reference

Base URL: `http://localhost:8000`. Interactive docs at `/docs` (Swagger UI, auto-generated by FastAPI).

All responses are JSON. All data is DEMO/SIMULATED unless noted.

## REST endpoints

### Dam
| Method | Path | Description |
|---|---|---|
| GET | `/api/dam/status` | Static dam info + current summary KPIs |
| GET | `/api/dam/sensors` | Current sensor cards (value, unit, trend, status, sparkline) |
| GET | `/api/dam/health` | Dam Structural Health Score + explainable factors |
| GET | `/api/dam/risk` | Dam Failure Risk Score + weighted contributing factors |
| GET | `/api/dam/anomalies` | Currently active anomaly detections |

### Flood / Zones / Geography
| Method | Path | Description |
|---|---|---|
| GET | `/api/flood/status` | Scenario, breach stage, sim clock |
| GET | `/api/flood/zones` | Per-zone live flood state (depth, velocity, arrival, risk, evacuation status) |
| GET | `/api/zones` | Static zone geography (population, elevation, distance from dam) |
| GET | `/api/roads` | Live road state + line geometry (for the map) |
| GET | `/api/shelters` | Live shelter state (capacity/occupancy/flood risk) |
| GET | `/api/infrastructure` | Static infrastructure points (hospitals, schools, bridges, power) |
| GET | `/api/geo/dam` | Static dam geometry + river path |
| GET | `/api/routes?zone_id=` | Current / recommended / alternative evacuation routes for a zone |

### Alerts & Events
| Method | Path | Description |
|---|---|---|
| GET | `/api/alerts` | Currently active emergency alerts |
| GET | `/api/events?limit=` | Recent live event timeline entries |

### Simulation control
| Method | Path | Body | Description |
|---|---|---|---|
| GET | `/api/simulation/state` | — | Full consolidated state (same shape as the WebSocket payload) |
| GET | `/api/simulation/scenarios` | — | List of valid scenario IDs + current scenario |
| POST | `/api/simulation/start` | — | Resume the simulation loop |
| POST | `/api/simulation/pause` | — | Pause the simulation loop |
| POST | `/api/simulation/reset` | — | Reset to the NORMAL baseline |
| POST | `/api/simulation/scenario` | `{"scenario": "MAJOR_BREACH"}` | Trigger a scenario (`NORMAL`, `HEAVY_RAINFALL`, `RAPID_RESERVOIR_RISE`, `STRUCTURAL_ANOMALY`, `PARTIAL_BREACH`, `MAJOR_BREACH`) |
| POST | `/api/simulation/speed` | `{"speed": 5}` | Set playback speed multiplier (0.5–10) |

### Analytics
| Method | Path | Description |
|---|---|---|
| GET | `/api/analytics/history` | Time series for dam health, failure risk, every sensor, population exposure, flood depth, shelter occupancy (in-memory demo history) |

## WebSocket: `/ws/live`

On connect, the server immediately sends the current full state, then pushes a new `state_update` message every simulation tick (~1.5s real time, scaled by the speed multiplier).

```jsonc
{
  "type": "state_update",
  "timestamp": "2026-09-04T07:15:01.077Z",
  "sim_minutes": 12.5,
  "scenario": "MAJOR_BREACH",
  "running": true,
  "speed": 5,
  "breach_stage": "MAJOR",
  "sensors": [ { "sensor_id": "deformation_mm", "value": 8.7, "status": "HIGH", "...": "..." } ],
  "dam_health": { "score": 71, "label": "WARNING", "factors": [ "..." ] },
  "failure_risk": { "score": 82, "level": "CRITICAL", "factors": [ "..." ], "explanation": [ "..." ] },
  "anomalies": [ "..." ],
  "zones": [ { "zone_id": "zone_b", "flood_depth_m": 1.8, "arrival_time_min": 32, "...": "..." } ],
  "roads": [ { "road_id": "R05", "status": "CLOSED", "...": "..." } ],
  "shelters": [ "..." ],
  "alerts": [ "..." ],
  "events": [ { "timestamp": "12:30:20", "message": "MAJOR DAM BREACH scenario triggered", "category": "BREACH" } ],
  "summary": { "dam_health": 71, "failure_risk": 82, "flood_arrival_min": 32, "population_at_risk": 6900, "safety_margin_min": 14, "recommended_action": "IMMEDIATE EVACUATION PREPARATION" }
}
```

The frontend keeps exactly this object in its Zustand store and every page/component reads from it — there is no separate polling once connected.
